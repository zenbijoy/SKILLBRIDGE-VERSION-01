# SkillBridge V3 Authentication & Security Architecture

SkillBridge implements a zero-trust, role-based access control (RBAC) model across all API endpoints, Socket.IO gateways, and PostgreSQL database operations.

---

## 1. Authentication Lifecycle

1. **Client Authentication**:
   - Clients authenticate with Supabase Auth (`supabase.auth.signInWithPassword` or OAuth).
   - Supabase issues an asymmetric RS256/HS256 signed JSON Web Token (JWT).
2. **API Verification**:
   - The backend `auth` middleware extracts `Authorization: Bearer <token>`.
   - The token is verified using Supabase Auth JWT keys.
   - User identity (`req.userId`), account status (`req.userStatus`), and roles (`req.userRoles`) are injected into the request context.
3. **Suspended Account Lockdown**:
   - If `req.userStatus === 'suspended'` or `'banned'`, the middleware immediately returns `403 Forbidden` with `{ "error": "Account suspended" }`, terminating the request before any business logic executes.

---

## 2. Role-Based Access Control (RBAC)

The system enforces 4 hierarchical roles:
- `student`: Standard user role (can join public rooms, attend sessions, search, chat, and submit reviews).
- `tutor`: Verified skill holder (can schedule teaching sessions and accept volunteer teaching requests).
- `moderator`: Community moderator (can review reports, dismiss/resolve tickets, and moderate chat).
- `admin`: Platform administrator (can ban users, elevate roles, configure platform settings, and view full audit logs).

### Privilege Hierarchy Rules
- **Non-escalation**: Moderators cannot ban or alter accounts of other Administrators.
- **Self-protection**: Administrators cannot suspend or ban their own accounts.
- **Service Isolation**: Atomic functions like `join_room_service_atomic` and `award_reputation_atomic` have execution rights revoked from `PUBLIC`, `anon`, and `authenticated` roles, and are granted strictly to `service_role`.

---

## 3. Row-Level Security (RLS) & Private Buckets

- **Private Attachments Bucket (`attachments`)**: Direct public URL access is blocked. Files can only be downloaded via short-lived signed URLs generated by the backend after verifying conversation membership.
- **Private Resources Bucket (`resources`)**: Path prefix validation ensures users can only upload files under their owned user prefix (`{userId}/*`).
- **Bidirectional Blocking**: Blocked users are automatically filtered from search results, discovery feeds, mutual connections, and direct messaging channels via database subqueries.
