# SkillBridge Next-Gen: Media Pipeline & Storage Operations Guide

**Phase 4 Operational Runbook**  
**Document Classification:** Standard Operating Procedures (SOP)

---

## 1. Overview of Rich Media Flow

SkillBridge Next-Gen implements a **zero-Express-bandwidth** rich media architecture designed specifically for Render Free Tier limits (512MB RAM, shared CPU):

1. **Direct Presigned Uploads**:
   - The frontend requests an upload ticket from `POST /api/v1/feed/upload-ticket`.
   - The backend validates file type (`image/jpeg`, `image/png`, `image/webp`, `image/gif`) and maximum size (10MB).
   - An object key is generated (`feed/${userId}/${timestamp}-${random}.ext`) and registered in `public.media_objects` with `status: 'pending_upload'`.
   - A presigned PUT URL is generated by the active `StorageProvider` (Cloudflare R2 or Supabase fallback).
   - The client uploads the binary directly to the storage bucket.
   - **Result**: Zero large video or image binaries pass through Render Express, eliminating memory spikes and gateway timeouts.

2. **Publishing & Entity Linkage**:
   - When the post is published (`POST /api/v1/feed`), `media_object_ids` are verified against the user's ownership.
   - Rows are created in `public.campus_post_media(post_id, media_object_id, display_order)`.
   - The `media_objects` status transitions to `ready`.

## 2. Background Jobs & Render Free Tier Concurrency

Render Free Tier does not support separate always-on Celery/Sidekiq background workers. A naive continuous polling loop (`setInterval(..., 1000)`) in the web server process would consume CPU quota and prevent the server from sleeping when idle.

### Solution: Opportunistic Batch Processing
- **Queue Table**: `public.background_jobs` tracks job types, priority, attempts, backoff schedule, and dead-letter classification.
- **Trigger Mechanisms**:
  1. **Opportunistic Execution**: Non-blocking `setImmediate(() => processBatch(3))` whenever an event or recording sync is enqueued.
  2. **Admin Cockpit Manual Trigger**: Administrators can click **Run Job Queue Batch** in `admin/src/pages/NextGenOperations.tsx` (calls `POST /api/v1/admin/nextgen/jobs/run`).
- **Exponential Backoff**:
  - If a job fails, `attempts` is incremented and `scheduled_for` is set to `now() + (30 * 2^attempts) seconds`.
  - Once attempts exceed `max_attempts` (default 5), the job moves to `dead_letter` status for admin inspection.

## 3. Storage Sweep & Orphan Cleanup

If a student selects images in the composer but abandons the post without submitting, the uploaded objects would remain in `pending_upload` status.

### Cleanup Process
- Run manually via admin cockpit: **Run Media Sweep (24h+)** (calls `POST /api/v1/admin/nextgen/media/cleanup`).
- Or scheduled via background job: `MEDIA_CLEANUP`.
- **Criteria**:
  - `media_objects` in `pending_upload` status older than 24 hours.
  - Deletes physical files from Cloudflare R2 / Supabase Storage.
  - Updates database status to `deleted`.

## 4. Admin Cockpit Walkthrough

In the Admin Panel under **Operations Control Plane > Media & Automation**:

1. **YouTube Integration Card**: Inspects OAuth status, API key availability, and count of active teacher channels.
2. **LiveKit Egress Card**: Confirms that egress automation is safely disabled by default.
3. **Queue & Sweep Controls**:
   - *Run Job Queue Batch*: Processes up to 10 pending background tasks immediately.
   - *Run Media Sweep (24h+)*: Deletes abandoned orphaned uploads older than 24 hours.
4. **Teacher YouTube Channels Table**: Lists connected teacher channels with channel ID and sync dates.
5. **Room Recordings Archive Table**: Shows all indexed room recordings with room ID, duration, status, watch links, and instant **Sync Meta** button.
6. **Recent Background Jobs Table**: Shows queue status (`completed`, `running`, `pending`, `dead_letter`) with error messages.
